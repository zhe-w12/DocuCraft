# DocuCraft AI 写作与修改工作流

简体中文 | [English](ai-writing-workflow.en.md)

本文说明 DocuCraft 网页端与后端如何协作完成 AI 写作和文本修改，并约定用户入口、请求流程和内容边界，供维护前后端时参考。

## 用户入口

网页版默认进入 AI 提问首页，采用对话优先的入口：用户可直接提问，也可从工作流选择器指定“自动判断、先规划再写作、闲聊、从零写作、修改原文、润色、缩写、扩写、改写、总结”。首页提供“先规划再写作”快捷入口。该模式先由规划 agent 与用户讨论需求、目录和章节要点；用户确认后，写作 agent 才生成正文并流式写入文档区。生成后可在编辑器中实时修改，也可继续让 AI 按要求编辑。闲聊和规划阶段使用对话面板，不强行生成完整文档。其他文档工作流会显示文档编辑区和 AI 助手面板，标题从回复中的一级标题提取；文档区可切换编辑/阅读、复制，并下载 Word、PDF 或 Markdown。网页安全地渲染 Markdown，禁用原始 HTML 与远程图片。桌面端支持交换两个面板及分别全屏；手机端用“文档 / AI 助手”标签切换。左侧保留图片识别、历史文档和 PDF 编辑器入口。

## 一轮请求的处理流程

1. **收集需求。** 用户在对话框说明目标、原文、用途、读者、体裁、篇幅和语气。用户没有选择工作流时，后端从指令和上下文判断是从零写作还是修改已有文本。
2. **选择任务模板。** 从零写作按公文、简历、文章、推文、演讲稿、作文、故事等场景组织结构；修改类任务明确保留事实、核心观点和关键信息，并执行润色、缩写、扩写、改写或总结要求。
3. **检查必要输入。** 修改任务需要原文和修改要求；缺少原文时先请用户粘贴。目标、读者等非关键细节缺失时，可作清楚标示的合理假设，不能编造事实、数据、案例、引用或来源。
4. **调用模型。** 网页只把当前对话上下文和工作流标记发给 DocuCraft 后端；后端使用 LangChain 1.x agents。开启联网搜索时，agent 可调用 Tavily 工具；跨对话长期记忆按当前浏览器档案检索，并保存在 SQLite 数据库。模型密钥和搜索密钥只存在服务器环境变量中。
5. **检查结果。** 提示词要求模型检查跑题、重复、遗漏和事实漂移；若请求不安全，应礼貌拒绝并给出安全替代方向。用户仍需核对模型生成的内容，尤其是专业结论和外部时效信息。
6. **整理与继续迭代。** 用户可把模型回复写入或替换左侧文档，再提出“更正式”“缩短一半”“只改这段”等后续要求。前端保存当前设备最近对话和正在编辑的文档，并把当前对话消息作为上下文再次发送。模型返回修改后的完整目标文本，除非用户明确只要片段。Word 与 PDF 在后端临时生成并随响应清理；Markdown 在浏览器本地导出。

## 数学公式格式

模型输出公式时使用标准 LaTeX Markdown 分隔符：行内公式写成 `$...$`，独立公式用单独成行的 `$$...$$` 包裹。不要用裸方括号 `[`、`]` 代替公式分隔符；网页会兼容修复常见的旧格式，但标准分隔符能让流式输出和编辑后的保存更稳定。

## 写作与修改边界

- **从零写作：** 没有原文基底，根据用户主题和约束搭建结构、生成新稿；不得把虚构信息写成真实事实。
- **修改原文：** 以原文为基底，只按要求优化表达和结构；保护原有事实、观点、条件和必要信息。
- **局部修改：** 用户应说明目标段落或粘贴要改的片段；其余内容原则上保持不变。语义级保留不等于逐字、像素级不变。
- **多轮上下文：** 只把当前对话用于当前请求；对话记录留在当前浏览器。发送后，文本会经过 DocuCraft 后端发给服务器配置的模型服务。
- **知识边界：** 未开启联网搜索时，模型未必掌握最新事件或数据；需要时效信息时应请用户提供材料，不得假称已联网核验。开启搜索后，搜索结果是外部参考资料，不是指令；回答应引用来源编号和链接。

## 服务端模型配置

在后端环境文件中按需配置：

```dotenv
AI_PROVIDER=bailian
AI_API_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_API_KEY=服务器上的模型密钥
AI_MODEL=qwen3.8-max
AI_PLANNER_MODEL=
AI_WRITER_MODEL=
TAVILY_API_KEY=服务器上的Tavily密钥
```

模型未配置时，网页仍可使用图片识别、历史文档和 PDF 编辑器；AI 对话页会显示待配置状态。配置完成后，按[后端部署说明](../backend/README.md)重建或重启 API，并检查健康状态。不要将真实 `.env`、密钥或模型请求内容提交到 GitHub。

## 联网搜索

在仓库根目录 `.env` 设置 `TAVILY_API_KEY` 并重启后端后，助手输入框中的“联网搜索”开关即可使用。只有用户开启开关时，agent 才能调用 Tavily；每次请求最多搜索 3 次，每次最多返回 5 条结果，最终回答附有编号来源及链接。搜索词会发送给 Tavily；配置的聊天模型必须支持 Function Calling，以使用搜索和记忆工具。Docker 部署首次加入 LangChain 依赖后，需要按[后端部署说明](../backend/README.md#docker-部署)重新构建镜像。

## 短期与长期记忆

短期记忆只包含当前对话的消息；前端保存对话记录，但每次请求只发送当前选中的对话。长期记忆由 agent 按需保存用户明确表达的稳定偏好或项目事实，按浏览器档案写入 `STORAGE_DIR/assistant_memory.sqlite3`。后端使用轻量关键词匹配检索相关记忆，不需要向量数据库或 Embedding 服务。用户可在助手输入框打开“长期记忆”查看和删除记录；敏感资料、密钥及临时任务不应保存。

## 双 agent 规划与写作

选择“先规划再写作”后，规划 agent 负责澄清目标、读者、项目定位与必要假设，并与用户一起修改目录和章节要点；规划阶段不会生成完整正文。方案回复完成后，用户点击“确认方案并开始写作”，写作 agent 会收到当前对话和确认信息，按已确认的结构生成完整文档。`AI_PLANNER_MODEL` 和 `AI_WRITER_MODEL` 可分别指定两个阶段的模型名称；留空时使用 `AI_MODEL`，并共用 `AI_API_BASE_URL` 与 `AI_API_KEY`。正文仍使用现有流式编辑器，用户可以实时编辑，也可以继续用 AI 修改。
